## 1. The problem T4 solves

So far, everything has been proven against a **mock coordinator inside one EVM**. Gate 5A will create **public state you can't undo**: a Raffle whose subscription ID is `immutable`, a consumer registration, and real LINK spending. T4 answers one question before that:

> *If I broadcast this exact revision, with this config and this key, will the chain end up where I expect? And do I know what to do if it doesn't?*

There are four concrete gaps today:

| Gap                            | Evidence in the repo                                                                                                                                                                                                                                                                                                                    | Consequence if left open                                                                                                                                                                                                       |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **G1 Dangerous config path**   | [DeployRaffle.s.sol:33-42](script/DeployRaffle.s.sol#L33-L42) creates a subscription whenever `subscriptionId == 0`, on any chain. The live ID is `keccak256(msg.sender, blockhash(block.number - 1), coordinator, nonce)` ([SubscriptionAPI.sol:374-380](lib/chainlink-evm/contracts/src/v0.8/vrf/dev/SubscriptionAPI.sol#L374-L380)). | `forge script` computes the ID while simulating at block N. The real create lands in a later block and gets a different ID. The result is an orphan subscription and a Raffle with a **permanently wrong `i_subscriptionId`**. |
| **G2 Silent success**          | The script never checks its own result. Only the local test [DeployRaffleTest.t.sol:37-40](test/integration/DeployRaffleTest.t.sol#L37-L40) does.                                                                                                                                                                                       | A Sepolia simulation can "succeed" while the owner, subscription or consumer is wrong (R9/R16).                                                                                                                                |
| **G3 Assumptions that expire** | VRF parameters, subscription balance and pending requests are a historical snapshot (18 LINK, block `11792671`). `MAX_PLAYERS = 60` is valid only for `callbackGasLimit = 500000` on the measured build (F3).                                                                                                                           | Broadcasting against stale facts. If someone changes the gas limit, the cap stops protecting liveness.                                                                                                                         |
| **G4 No operating procedure**  | Nothing is written for a stalled fulfillment, the F2 rule, teardown, key handling or preserving evidence (`broadcast/` is gitignored, [.gitignore:6](.gitignore#L6)).                                                                                                                                                                   | During an incident you improvise. The owner override is tempting but would invalidate the demo.                                                                                                                                |

**What T4 produces is not a deployment.** It produces a reviewed config, a passing **non-broadcast** simulation and a short runbook. The evidence label stays A/B1, and nothing here counts as C1.

> 中文：至今所有证据都来自单个 EVM 里的 mock。Gate 5A 会产生不可撤销的公开状态，所以 T4 要回答："用这个版本、这个配置、这个 key 广播，链上结果是否如预期？出问题时知道怎么办吗？" 四个缺口：危险的订阅创建路径、脚本不验证自身结果、会过期的假设（含 F3）、没有事故流程。T4 的产出是配置 + 模拟 + runbook，不是部署。

## 2. How it is solved: put each assumption in the cheapest place that fails loudly

| Kind of assumption                                                                 | Mechanism                                                                     | Why                                                                                                |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Config rules that code can check (subId ≠ 0 off-chain, gas limit = measured value) | Revert in HelperConfig/DeployRaffle, plus a local test                        | Fails on every run, including the Sepolia simulation                                               |
| What the deploy actually produced (owner, consumer, coordinator, subId)            | **Post-deploy assertions inside the script**                                  | They run during `forge script` simulation against real chain state, so nobody has to read the logs |
| Chain facts (parameters, balance, pending requests)                                | `cast call` reads, recorded with date and block, plus the re-pinned fork test | Facts change over time, so record *when* each was true                                             |
| Human decisions (budget, interval, teardown, F2, incident steps)                   | A short written runbook                                                       | Code can't decide these                                                                            |

> 中文：能用代码检查的放进代码（会在模拟中自动失败）；链上事实用带区块号的读数记录；人的决策写进 runbook。

### Task 2.2: budget and interval (checklist items 3 and 5; R15, F1)

The billing formula, taken from `_calculatePaymentAmountLink` ([VRFCoordinatorV2_5.sol:568-600](lib/chainlink-evm/contracts/src/v0.8/vrf/dev/VRFCoordinatorV2_5.sol#L568-L600)):

$$
\text{payment}_{\text{juels}} = \frac{10^{18}\, p_{\text{gas}}\,(G_{\text{after}} + G_{\text{fulfill}})}{w_{\text{LINK}}} \cdot \frac{100 + P_{\text{link}}}{100} + \frac{10^{18} \cdot 10^{12}\,(F_{\text{native}} - D_{\text{link}})}{w_{\text{LINK}}}
$$

Plain text: `payment = 1e18 * gasPrice * (gasAfterPaymentCalculation + gasUsedInFulfill) / weiPerUnitLink * (100 + linkPremiumPercentage) / 100 + 1e30 * (flatFeeNativePPM - flatFeeLinkDiscountPPM) / weiPerUnitLink`.

- $p_{\text{gas}}$ is the fulfilling transaction's gas price. Its upper bound is the lane's max gas price from 2.1.
- $G_{\text{fulfill}}$ = `startGas - gasleft()`. It covers everything inside `fulfillRandomWords`: proof verification **plus** your callback.
  - Your callback is ≤ 500000 (425,607 measured at 60 players).
  - The verification part is **not** measured in this repo. Either use an explicit allowance and say so, or optionally read the `payment` field of a recent real `RandomWordsFulfilled` on this coordinator and work backwards. Public RPCs may limit `cast logs` block ranges.
- The checklist's "~0.37 ETH-equivalent worst case" is `500 gwei × (112,000 + 500,000) × 1.2`. Recompute it with **your** 2.1 values.

The budget rule, which is the key point:
- `performUpkeep` is permissionless (R15), and one actor can fill every round (F1). So **anyone can spend the whole subscription balance**.
- The funded amount is therefore not "what the demo needs". It is **the most you accept to lose**.
- Size it as: planned rounds × worst-case cost per request + a margin. Keep it small.

Interval decision (HelperConfig `INTERVAL = 30`):
- A longer interval slows a griefer down but **does not lower the maximum loss**, because the balance caps that.
- Changing the interval also changes a constant and the Raffle's constructor argument.
- It does not affect F3: callback gas doesn't depend on the interval.
- My recommendation, in line with your "change as little as possible": keep 30 s, fund small, and tear down right after the demo. Pick your option and write down why.

Design questions:
1. Why is "the balance is the maximum loss" true no matter what the interval is?
2. With your numbers, how many worst-case requests does the amount you plan to fund cover? How many typical ones (20 players)?
3. When you tear down, where does the unspent LINK go? (See 2.3.)

**Record:** each input value with its source, the worst-case and typical cost per request, the funded amount, the interval decision, and the R15/F1 acceptance in one sentence.

> 中文：按源码中的计费公式，用 2.1 的真实值重新计算单次请求成本；验证部分的 gas 未在本仓库测量，需要声明估计值。关键结论：任何人都能花光订阅余额，所以充值金额等于"愿意承担的最大损失"。interval 只影响消耗速度，不影响上限；建议保持 30 s、少量充值、演示后立即拆除。

   Don't use `run()`, which picks the most recent deployment from the local `broadcast/` folder. Or use `forge script … --resume` with `broadcast/` and `cache/` intact.
3. **Correlating a round:**
   - the `performUpkeep` transaction emits `RequestedRaffleWinner(requestId)`;
   - the fulfillment transaction emits the coordinator's `RandomWordsFulfilled(requestId, …, subId, payment, …, success)` together with `PickedWinner` and `WinningCredited`;
   - a `success == false` with `CALCULATING` still set is the stuck state from T3.1.
4. **Stalled fulfillment:** stop further testing, read `RandomWordsFulfilled.success`, the subscription balance and the Raffle state, and keep the evidence.
   - The owner override is **not** a recovery: it would invalidate the VRF demo.
   - **F2:** if the override is ever used while a request is pending, never repoint `setCoordinator` back to the live coordinator until that request has been fulfilled or has failed.
   - Stopping yourself doesn't stop public entries.
5. **Teardown:** once `pendingRequestExists(newSub) == false`, call `cancelSubscription(newSub, <owner>)`. It requires no pending request and returns the remaining LINK ([VRFCoordinatorV2_5.sol:689](lib/chainlink-evm/contracts/src/v0.8/vrf/dev/VRFCoordinatorV2_5.sol#L689)). `removeConsumer` alone keeps the LINK in the subscription. Decide which one you want and why.
6. **Evidence:** `broadcast/` is gitignored, so copy transaction hashes, blocks and addresses into records. The key stays in `.env` with only testnet funds and never goes into logs.

> 中文：runbook 约 15 行：广播前检查、部分广播的恢复（用显式地址注册，不重新部署）、按 requestId 关联事件、fulfillment 卡住时的处理（不用 owner override；F2 规则）、拆除（`cancelSubscription` 会退回剩余 LINK）、证据保存。
